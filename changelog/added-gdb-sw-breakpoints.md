The GDB server now manages software breakpoints itself: Z0/Z1 packets patch the original ebreak encodings into target memory (byte-granular, so compressed instructions at 2-mod-4 addresses work) and restore them around stepping and resuming. Stepping or continuing off a breakpoint executes the real instruction - including jumps, which land on their actual target - instead of skipping it, breakpoint stops are reported as `swbreak` rather than SIGINT, and reads present the original instruction at breakpoint addresses. Breakpoints are cleaned up on disconnect, reset and flash commits.
